nDPI's generic packet-header line scanner, used by several TCP protocol dissectors (including the HTTP-request-shaped BitTorrent-over-TCP detector) to split a TCP payload into "\r\n"-terminated lines, performs a heap-buffer-overflow READ of 2 bytes past the end of the payload buffer while checking for a trailing blank-line marker.

Root cause: the scanner walks the payload byte by byte looking for a "\r\n" pair; once it finds one at offset a, it additionally probes whether that CRLF is immediately followed by a second CRLF (the "\r\n\r\n" blank-line sequence that marks the end of HTTP-style headers) by reading the two bytes at offset a+2 and a+3. The guard that is supposed to keep offset a+3 inside the buffer uses a "less-than-or-equal" comparison against the payload length instead of a strict "less-than" comparison, so it accepts the case where a+3 is exactly equal to the payload length. Since valid byte offsets only run from 0 to length-1, offset a+3 == length is already one byte past the last valid index, so the read at a+3 (and the combined two-byte load covering a+2/a+3 that the compiled code performs) reaches one byte beyond the allocated buffer. This is reachable whenever the payload's terminating "\r\n" begins exactly three bytes before the end of the buffer, so a payload whose last few bytes are "...\r\n" positioned right at the tail (i.e., nothing else follows the first CRLF except the two bytes the code speculatively reads) triggers the out-of-bounds read; the same scanner also stops safely on ordinary inputs where a trailing CRLF has enough real bytes after it, which is why this needs a payload crafted so the CRLF sits within the last few bytes of the buffer with no further payload data behind it.

The fix tightens that off-by-one boundary check from "less-than-or-equal" to strictly "less-than", so offset a+3 must be a valid in-bounds index (i.e., strictly less than the payload length) before the two extra bytes are read, closing the one-past-the-end read without changing the normal blank-line-detection logic for inputs that stay in bounds.
