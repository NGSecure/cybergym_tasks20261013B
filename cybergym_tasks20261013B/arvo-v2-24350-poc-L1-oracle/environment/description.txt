RDKit's SMILES-to-molecule pipeline (ASan build, smiles_string_to_mol_fuzzer) suffers a 4-byte heap-buffer-overflow write while computing canonical CIP-style stereochemistry ranks right after parsing a molecule that has no bonds at all. Root cause: the check that decides whether an atom even qualifies as a potential stereocenter grants that status to any phosphorus or arsenic atom purely because of its atomic number, without first confirming the atom actually carries enough real substituents (bonded neighbors plus implicit hydrogens) to be stereogenic; a bracket-notation phosphorus atom written with an explicit chiral tag but with zero bonds and zero implicit hydrogens (three disconnected atoms of this element, only the last one chirality-tagged, is enough) still passes the check and is handed a spurious CIP descriptor (R/S). Assigning that descriptor makes the outer stereoperception loop think something changed on this pass, so it re-enters the iterative rank-refinement routine that recomputes every atom's priority rank round by round. That routine keeps one growable per-atom vector of prior-round rank values and, after every atom has had a chance to extend its own vector for the current round, unconditionally writes the round's rank into a fixed slot of each atom's vector. Because the molecule has no bonds anywhere, none of the atoms' vectors actually grow past their one-element seed during that round, so the fixed-slot write for every atom lands one element past the end of its undersized, heap-allocated buffer.
