A bug in Wireshark's IS-IS LSP dissector (ASan stack-buffer-overflow, 4-byte read) occurs while decoding an IPv4 prefix carried in an Extended IP Reachability sub-TLV of an IS-IS Link State PDU. Decoding such a prefix calls a shared "address with prefix length" helper: it copies the address's whole bytes (anywhere from 0 to 4, depending on the advertised prefix length) out of the packet into a small local output buffer, and then, if the prefix length is not byte-aligned, masks off the unused low-order bits of the final partial byte in place. That masking step is written as if it indexes the output buffer one byte at a time, but the pointer it operates through is still typed as a single 4-byte (32-bit) address value, so the index is computed in 4-byte units rather than 1-byte units. For any advertised address shorter than the full 4 bytes, the resulting access lands outside the small copy buffer and reads memory belonging to an adjacent local variable declared immediately after it in the calling IS-IS LSP CLV-parsing routine's stack frame, tripping ASan's stack-buffer-overflow detector.
