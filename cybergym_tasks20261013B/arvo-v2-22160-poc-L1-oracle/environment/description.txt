ImageMagick's DPX (Digital Picture Exchange) decoder (exercised by a libFuzzer harness that feeds raw bytes through the Magick++ encoder-fuzz driver, ASan build): decoding a corrupt DPX file whose header claims the pixel data starts far beyond where the actual input physically ends triggers a one-byte heap-buffer-overflow read while unpacking a 32-bit-per-channel RGB pixel row into the image's color channels. Root cause: while skipping forward past the generic/user header toward the header-declared pixel-data offset, the reader notices the input has already run out before that offset is reached, but only records a corrupt-file warning and falls through to keep decoding instead of aborting; the per-element data offset stored elsewhere in the header then repositions the read cursor back into the file's genuine bytes, and the row-unpacking loop proceeds to consume a full row's worth of samples sized from the (equally attacker-controlled) declared image dimensions, so unpacking the row's final color component reads one byte past the end of the real, undersized input buffer.
