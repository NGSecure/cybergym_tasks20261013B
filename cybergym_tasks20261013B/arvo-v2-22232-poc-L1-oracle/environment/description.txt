Heap-buffer-overflow (1-byte out-of-bounds read), detected by AddressSanitizer. It happens while the library builds the very first protocol layer for a packet read straight out of a pcap file: when the leading byte of a raw, only a few bytes long, packet buffer happens to carry the bit pattern of an IPv6 version marker, the code goes ahead and parses that buffer as a complete IPv6 header without first checking whether enough bytes are actually present to hold one. Root cause: the object representing that layer begins reading header fields and walking the chain of extension headers immediately upon construction, before any check that the packet's real captured length covers the full fixed-size IPv6 header, so on a several-byte truncated packet a fixed-offset header-field read runs past the end of the small heap allocation backing the raw packet data. The fix introduces a length-validation check that every call site which may construct this layer must pass first, falling back to a generic payload layer whenever the remaining bytes are too short to hold a full header.
