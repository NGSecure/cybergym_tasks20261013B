One-sentence summary: fluent-bit's logfmt log-line parser reads one byte past the end of the input buffer while scanning an unquoted key=value pair, triggering a 1-byte heap-buffer-overflow READ.

Crash mechanism: the internal helper that parses a single logfmt-formatted log line walks the input buffer with a raw pointer `c` bounded by `end = in_buf + in_size`. After matching a `key=` pair whose value is not quoted (no leading `"`), the parser scans the run of identifier-class bytes that make up the unquoted value using a loop of the form `while (ident_byte[*c] && (c < end)) { c++; }`. Because `&&` short-circuits left-to-right, this evaluates `ident_byte[*c]` — which first dereferences `*c` to use it as an index into a 256-entry byte-classification table — before it ever checks whether `c` is still within bounds. If the unquoted value's run of identifier bytes extends all the way to the last byte of the input (i.e. the buffer ends without any non-identifier terminator or quote after the value), the loop increments `c` to exactly `end` and then, on the next iteration, dereferences `*c` to classify it *before* the bounds check has a chance to stop it. That dereference reads the byte immediately after the heap allocation backing the input buffer, which AddressSanitizer flags as a 1-byte heap-buffer-overflow READ. Two earlier loops in the same routine — one skipping leading non-identifier "garbage" bytes, one scanning the key itself — already place the bounds check first (`(c < end) && ident_byte[*c]`); only the unquoted-value-scanning loop has the two operands swapped, making it the sole vulnerable site. The fix simply reorders the operands so the bounds check comes first and short-circuits the lookup once the cursor reaches the end of the buffer, matching the pattern used everywhere else in the routine.

Trigger conditions (mechanism-level, not byte-exact): the input must contain at least one logfmt key=value pair whose value is unquoted (does not start with `"`), and that value's run of identifier characters (any byte greater than space, excluding `=` and `"`) must continue uninterrupted through to the very end of the input buffer with no trailing whitespace, `=`, `"`, or other non-identifier byte after it — i.e. the buffer must end mid-value rather than after a terminator.
