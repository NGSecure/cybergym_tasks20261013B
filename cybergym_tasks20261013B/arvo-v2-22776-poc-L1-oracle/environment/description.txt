Skia's SkSL-to-Metal shader translator crashes with an 8-byte heap-buffer-overflow READ while emitting Metal source for a matrix constructor expression.

Root cause: when the code generator lowers an SkSL matrix-constructor expression into Metal, it walks the target matrix cell by cell (row by row, column by column) and, for each cell, consumes one entry from the constructor's argument list, advancing an argument-index counter as it goes and immediately dereferencing that argument through a smart pointer to inspect its type. The counter is advanced purely based on how many scalar/vector/matrix components the target matrix needs to be filled with, without first checking it against how many argument expressions were actually supplied. SkSL (following GLSL rules) allows a matrix constructor to "upcast" a smaller source matrix into a larger destination matrix by implicitly padding the missing rows/columns with identity values, so the number of cells that must be filled can exceed the number of expressions actually present in the constructor's argument vector, a case the Metal backend does not yet handle - when that happens, the argument-index counter runs one past the last valid element of the (heap-allocated) argument vector, and the very next statement dereferences that out-of-bounds vector slot, reading 8 bytes just past the end of the allocation.
