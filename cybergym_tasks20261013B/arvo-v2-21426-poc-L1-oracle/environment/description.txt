One-sentence summary: In Open vSwitch's datapath (ODP) flow-key/mask text parser, parsing a GTPU tunnel-option mask that specifies only one of its two optional sub-fields leaves the mask byte for the omitted sub-field uninitialized on the stack, and that uninitialized byte later gets read back out when the parsed flow is reformatted to text, tripping MemorySanitizer's use-of-uninitialized-value check.

Root cause / crash mechanism:
The GTPU tunnel-option mask parser (invoked while parsing a datapath flow key/mask string, e.g. via the "gtpu(...)" tunnel-option syntax) declares its per-sub-field "mask" shadow variables as plain stack locals without giving them a default value. The GTPU option syntax allows the caller to specify either or both of its two independent sub-fields (an 8-bit protocol-flags value and an 8-bit message-type value) in the mask text, each optionally followed by its own "/mask" suffix. The parser's control flow only assigns a sub-field's mask-shadow variable when that particular sub-field's key actually appears in the input text; if the input mask string mentions only one of the two sub-fields, the mask-shadow local for the sub-field that was never mentioned is left holding whatever indeterminate bytes were already on the stack.

That still-uninitialized byte is then unconditionally copied (via a generic memcpy-style helper used to propagate parsed values into the flow key/mask structure) into the corresponding byte of the in-memory GTPU-option mask, regardless of whether the sub-field was actually present in the input. The uninitialized taint therefore silently propagates from the stack into a heap/structure field that is treated as fully valid data downstream.

The crash itself does not fire at parse time. It fires later, when the resulting flow record is formatted back into human-readable text: the tunnel-option formatting path walks each byte of the GTPU option (including its mask) and renders it through a small generic helper that prints a single unsigned byte as hex. When that helper is handed the still-uninitialized mask byte for the sub-field that was omitted from the original input, MemorySanitizer flags the read as a use of uninitialized value, well downstream of and disconnected from where the uninitialized data was originally created.

In short: this is a missing-stack-initialization bug where an "all-or-nothing" assumption about a two-sub-field optional mask (assume both mask-shadow locals get written before use) is violated whenever the input legitimately provides only one of the two sub-fields, letting garbage stack data flow into a structure that is later read and printed as if it were fully initialized.
