RDKit's molfile-to-mol AFL/ASan fuzz target: parsing a crafted V2000 CTAB (connection-table) properties block triggers a heap-use-after-free read of 4 bytes. Root cause: the properties block first contains an obsolete-style atom-list property line that causes one of the molecule's existing Atom objects (allocated earlier while the plain atom block was parsed) to be swapped out for a replacement and deleted, but a bookmark that had been recorded against that same atom index while the atom block was parsed is never invalidated when the swap happens. A later substance-group (SGroup) vector-data property line further down in the same properties block resolves that now-stale bookmark back to the freed Atom pointer and reads its stored index field off it, dereferencing already-freed heap memory.
