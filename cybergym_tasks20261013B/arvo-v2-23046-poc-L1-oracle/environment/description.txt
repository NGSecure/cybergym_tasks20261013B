nDPI's HTTP dissector (ASan build): once HTTP has been provisionally guessed for a flow, the module keeps handing the same content-classification check a few more TCP segments so it can be re-run to firm up the guess, but the pointer/length pair it reads for the Content-Disposition header is populated only when that header is actually present in the segment currently being parsed and is never cleared before a new segment is handed in, so a later segment in the same flow that has no Content-Disposition header of its own still carries over the pointer captured from an earlier segment whose backing packet buffer has by then already been released, and the classification check dereferences that stale pointer.
