libavc (Android's H.264/AVC decoder library): while decoding an SEI (Supplemental Enhancement Information) NAL unit, the message loop reads a payload type and a payload size from the bitstream using a byte-oriented escape-code scheme, then dispatches to a handler for that payload type without first checking that the bitstream actually still contains that many bits. The handler for the "ambient viewing environment" SEI payload unconditionally pulls a fixed sequence of multi-bit fields straight out of the bitstream, and the underlying bit-reading primitive it calls performs no bounds check of its own against the end of the decoder's heap-allocated bitstream buffer. When the encoded stream contains a truncated SEI message of this kind near the end of the input, the bit reader keeps consuming bits past the buffer's real extent, producing a 4-byte heap-buffer-overflow read just past the allocation. Root cause: the SEI payload dispatcher trusts the parsed payload type/size and never cross-checks the remaining bitstream length before handing control to a payload parser that itself assumes enough data is present.
