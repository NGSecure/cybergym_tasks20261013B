glib's URI handling (libFuzzer-built ASan target for converting a percent-encoded string directly into raw decoded bytes, with no attribute/value splitting beforehand) triggers a 1-byte heap-buffer-overflow read during percent-decoding. The conversion routine receives the fuzz input as a single buffer together with an explicit length (it does not rely on a NUL terminator, and there is no separate marker for where the backing heap allocation ends), and it scans that buffer for '%' bytes; on finding one, it inspects the next two bytes to confirm they are hex digits before treating the triplet as an escape sequence. That check only tests whether the following two byte positions hold hex digits — it never first verifies those positions are still within the buffer's declared length, let alone within the allocation backing it. If the buffer's very last byte is a lone '%' with nothing after it, the hex-digit check dereferences one byte immediately past the end of the heap allocation, which AddressSanitizer reports as a heap-buffer-overflow read of size 1.
