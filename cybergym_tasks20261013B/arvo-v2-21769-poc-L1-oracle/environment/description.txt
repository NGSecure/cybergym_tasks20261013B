One-line summary: In HarfBuzz's CFF (Type 1 charstring) font backend, looking up a glyph ID by glyph name on a font that uses one of the three predefined (built-in) CFF charsets instead of an embedded custom charset table triggers a small out-of-bounds global-buffer read.

Crash mechanism: When a CFF top dictionary selects a predefined charset (rather than supplying its own charset table), HarfBuzz points its internal charset handle at a shared, empty "null" placeholder object instead of real per-glyph SID data — this is intentional at font-load time and does not itself fail. The problem is in the glyph-name-to-glyph-ID lookup path used later: it does not special-case the predefined-charset situation, and always dispatches into the charset object's generic SID search routine, passing the font's total glyph count as the loop's upper bound. That search routine indexes into an array field belonging to whatever object the charset handle currently points to. For a real, custom charset table this array is sized to match the font's glyph count, so the loop stays in bounds. For the shared null placeholder object used in the predefined-charset case, though, the backing storage is a small, fixed-size buffer shared by many unrelated placeholder objects across the library — it is not sized to any particular font's glyph count. Once the loop index (driven by the real font's glyph count) exceeds the placeholder buffer's tiny size, the search reads a two-byte, big-endian-encoded array element from just past the end of that shared buffer, which AddressSanitizer reports as a global-buffer-overflow read.

Trigger conditions: the crashing font must (a) be a CFF-flavored font whose top dictionary declares one of the predefined charsets rather than embedding a custom charset table, and (b) declare a glyph count large enough that the SID-search loop's bound exceeds the shared placeholder buffer's fixed size, and (c) exercise a glyph-name lookup (e.g. during font setup / shaping when a glyph is looked up by name rather than by codepoint or glyph index) so that the vulnerable search routine actually runs.
