Perfetto trace_processor's trace-parsing fuzz target (ASan build): parsing a proto trace packet that declares a track descriptor with a parent-track reference triggers a heap-use-after-free read while the track-descriptor resolver walks the chain of ancestor tracks. Root cause: this resolution logic recurses up the parent-track chain, and the outermost call in that walk lazily heap-allocates a small ancestor-tracking container (used to bound recursion depth and detect cycles) owned by a smart pointer whose scope is the block performing the walk; a raw, by-value pointer to that same container is threaded down through the recursive calls. Once the walk finishes and that owning block exits, the smart pointer's destructor frees the container - but the outer function's own local copy of the raw pointer is left dangling instead of being cleared. Later in that same function, after the recursive ancestor walk has already returned, code further down still dereferences that stale local pointer to iterate the container again, reading through an already-freed heap allocation. Because this depends on triggering the "no ancestor list passed in yet" (outermost) case of the resolver for a track whose parent chain is later probed, only certain relationships between a track's own descriptor and its declared parent uuid, processed in the right order, exercise the dangling reuse; unrelated tracks with no parent reference, or resolutions that are never the outermost call in their chain, do not.
