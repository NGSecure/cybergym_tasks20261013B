This crash comes from a compile-only PHP source-parsing fuzz harness (php-src's Zend Engine, ASan build) that feeds raw PHP source text straight into the compiler and never executes the resulting bytecode. The reproducer is a tiny script that applies PHP's nullsafe property-access operator (`?->`) directly to an array literal (an array built from a single empty-string element) rather than to a variable, followed by an arbitrary property-name byte. Because the left-hand operand is a literal rather than something that needs a runtime temp, the compiler folds it once into a compile-time constant and stores it in the compiled function's constant/literal table. That same constant is then referenced from two different places in the generated instruction stream: the short-circuiting null-check jump that the nullsafe operator always emits ahead of the property access, and the separate instruction that actually performs the property read. The code path that emits the null-check jump embeds a handle to the constant into that jump instruction as if it were a new, independent owner of the array value, but it does not take the reference-count increment that a second owner requires. The cleanup logic that runs when the compiled function's table of constants is released afterward, however, still assumes every instruction referencing a given constant is a properly counted owner, and walks each reference in turn to drop the count by one. The first pass correctly drives the array's reference count to zero and frees its heap allocation. The second pass, belonging to the instruction whose ownership was never actually counted, then reads the reference-count field of that same, now-freed array in order to decrement it again — a 4-byte heap-use-after-free read. The fault is fully deterministic and content-independent: the array only needs to be a compile-time constant (any short array literal works), and the token following the nullsafe arrow can be any byte usable as a property name; no execution of the compiled script is required, only compilation.
