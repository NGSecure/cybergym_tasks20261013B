RDKit's mol-block-to-molecule fuzz target (ASan build): parsing a crafted V2000 SDF/MOL property block triggers an invalid-free. Root cause: while scanning a molecule-property line for an embedded Marvin-format SMARTS annotation, the parser checks only a handful of characters at a fixed column offset against the expected "SMA" marker instead of matching the whole expected line prefix, so an unrelated or malformed property line whose bytes happen to coincide at that offset is misidentified as a genuine Marvin SMARTS line. The parser then unconditionally treats everything past a fixed later offset in that same line as SMARTS text and hands it to the embedded SMARTS-string parser. Because the line was never actually a well-formed Marvin SMARTS annotation, this bogus text can contain unbalanced recursive-pattern ("$(...)") syntax; the SMARTS parser's internal state stack, used to track nested recursive-pattern scopes while it consumes the string, is popped one time too many with no matching entry ever having been pushed, corrupting the stack's bookkeeping. When that corrupted bookkeeping is later released, the resulting free targets memory that was never allocated on the heap in the first place.
