njs (NGINX JavaScript engine) UBSan build, script-processing fuzz target: constructing a plain user-defined JavaScript function with `new` (invoking it as a constructor, e.g. `new r()`) triggers a bad-cast / out-of-bounds member access while the bytecode interpreter sets up and runs the constructed function's own local execution frame. UBSan reports a pointer dereference into a region that has less room left than a single complete tagged JS value needs, meaning the local/scope storage block reserved for that function's own call frame is narrower than one full value slot. The crash reproduces even for a function with an empty body and no explicit parameters or local variables, which shows the frame-size computation itself under-allocates for the constructor-call case rather than mishandling any particular declared variable or bytecode instruction -- consistent with the interpreter's per-call frame sizing failing to reserve the extra implicit value slot a constructor invocation needs (for the freshly created `this` object) beyond what an ordinary, non-constructor call of the same function would require, so a later read/write through that slot walks past the end of the allocated frame region.
