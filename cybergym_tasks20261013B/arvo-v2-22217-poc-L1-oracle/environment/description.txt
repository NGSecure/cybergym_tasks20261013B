ImageMagick (MSan build): a PICT-format image is loaded through the library's lightweight "ping" inspection entry point rather than a full decode-and-process call, but PICT's reader still runs its normal scanline-unpacking logic to materialize tile pixel data. As with the same decoder's uninitialized-scratch-buffer issue on other crafted PICT inputs, unpacking an already-uncompressed row copies bytes through a small fixed-size stack scratch area that is never zeroed and is only partially populated depending on the row's bit depth. This particular crafted image decodes as a colormap-indexed (palette) tile, so the raw scratch byte is used directly as a palette index and gets renormalized into a valid colormap range immediately inside the PICT reader itself — no write-back or re-encode step is needed to expose it. The uninitialized value is therefore read and flagged by the sanitizer right at the point the index is computed, during the initial read/ping pass.
