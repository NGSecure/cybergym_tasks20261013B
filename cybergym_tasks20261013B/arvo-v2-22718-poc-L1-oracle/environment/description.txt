RDKit's legacy V2000 MDL-molfile reader (UBSan build) performs an invalid downcast while resolving deferred atom queries after a molecule block finishes parsing. Root cause: a per-atom property line whose true value cannot be known until the full molecule graph exists (e.g. a substituent-count / ring-bond-count / unsaturation constraint) is represented by first promoting the plain atom to a query atom with a simple equality-style leaf query, then AND-combining a second leaf query that carries a "resolve later" sentinel value into it; this AND-combination always replaces the atom's top-level query object with a brand-new compound query node whose two children are the original leaf and the sentinel-bearing leaf — the top-level object is never itself a leaf once this happens. A post-parse completion pass that later scans every query-bearing atom to substitute the sentinel value unconditionally casts each atom's top-level query pointer down to the simple leaf-query type before calling that type's own accessor/mutator and walking its children, without checking whether the pointer actually references a leaf or the compound node produced above. Because essentially any atom touched by one such deferred-value property line ends up with a compound top-level query, the cast reinterprets an incompatible polymorphic query subtype as the leaf type it is not — undefined behavior reachable with a single such per-atom property line in the input molfile.
