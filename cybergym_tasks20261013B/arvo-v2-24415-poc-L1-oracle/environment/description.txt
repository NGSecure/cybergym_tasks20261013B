OTS (OpenType Sanitizer, used by browsers to validate untrusted font files before rendering; MSan build): processing a malformed TrueType Collection -- a container format in which several fonts can share the same underlying table bytes -- triggers a use-of-uninitialized-value read. A newly allocated variable-font axis table is registered into the current font's table list before its own field-by-field parse has actually run; when that parse aborts on its very first read failure, none of the table's numeric fields (including its axis count) are ever written. The sanitizer's cleanup routine for bad variation data then runs, which drops the half-built table from the current font's list but still reports success to its caller, so the still-uninitialized table object gets cached into the collection-wide table store as though it had parsed correctly. A second font in the same collection that happens to share that exact table then reuses this cached, half-initialized object; when that font's glyph-variation table cross-checks its own declared axis count against the axis table's axis count, it reads the field that was never written, and MemorySanitizer flags the read. The fix makes the table lookup used for this kind of cross-check refuse to hand back a table that has been dropped/discarded, so a half-built table is now treated as simply absent instead of being served up with stale, uninitialized data.
