nDPI's TLS certificate parser assembles the certificate's subject/issuer distinguished name by repeatedly appending each recognized X.509 attribute (Common Name, Country, Organization, etc.) into a fixed-size stack buffer as it scans the handshake payload, but never checks whether the running write offset has already reached that buffer's capacity before appending the next field. Root cause: a crafted certificate with enough repeated attribute fields drives the offset past the buffer's size; because the "remaining space" for the next append is computed as an unsigned subtraction, once the offset exceeds the capacity that subtraction wraps around to a huge value, so the append keeps writing well beyond the end of the stack buffer instead of stopping, silently corrupting adjacent stack memory. That corruption clobbers a nearby pointer-sized value that downstream flow-reporting code later trusts as a valid, NUL-terminated heap string for the parsed DN field; when that code duplicates the string, the duplication routine calls strlen() on the now-wild pointer, and dereferencing it triggers the SIGSEGV read fault seen in the crash.
