nDPI's HTTP dissector (ASan build): when classifying a detected HTTP flow as a binary-file/attachment transfer, the code derives a byte offset into the already-parsed Content-Disposition header value purely from the filename substring's own length and then compares a fixed-width chunk starting at that offset against a table of known file-extension strings, without first checking that offset-plus-width still fits inside the header value's recorded length; on a Content-Disposition value whose filename portion is long enough to pass an earlier minimum-length check but leaves too little room for the computed offset, the comparison walks past the end of the packet-line buffer backing that header and reads bytes that have already been freed.
