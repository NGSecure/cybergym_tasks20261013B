LibRaw (MSan build): a malformed floating-point DNG file with an inconsistent declared bit-depth and dimension combination that should have been rejected during raw-file validation is instead accepted, and by the time processing reaches the demosaic algorithm's red/blue-channel color-space conversion step, part of that algorithm's own internal working buffer -- sized according to the file's invalid declared geometry -- was never populated for this particular degenerate image, so the conversion step reads uninitialized heap memory while it borrows neighboring cells to build each output value. Root cause: the acceptance check that would normally reject a floating-point DNG file whose declared bit depth falls outside the narrow range the decoder actually supports was missing an upper bound, so the file passes initial raw-file validation with a bit-depth/dimension combination the rest of the pipeline never expects; the demosaic algorithm's per-cell loop bounds, computed from that same invalid geometry, then don't line up with how much of its internal buffer was actually written, leaving a subset of cells uninitialized when the color-space conversion step later reads them.
