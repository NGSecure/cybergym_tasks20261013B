nDPI (ASan build under the libFuzzer packet-processing harness, reached here through the BitTorrent protocol detector's zero-connection search path): while scanning a TCP payload byte-by-byte for a CRLF ("\r\n") end-of-line marker, once one CRLF is found the code looks two bytes further ahead for a second CRLF pair, to detect a blank line ("\r\n\r\n", i.e. end of a header block). A bounds check guards this second, farther-ahead probe, but it is exactly one byte too permissive: it lets the probe's position land right at the payload's length instead of stopping one byte earlier. Because that probe reads its two bytes as a single, unconditional two-byte load (rather than two independent byte comparisons that would short-circuit before touching the second byte), when the CRLF happens to sit close enough to the tail of the payload that this off-by-one lets the check through, the load touches one byte past the end of the heap-allocated payload buffer, producing a 2-byte heap-buffer-overflow read.
