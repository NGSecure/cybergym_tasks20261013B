Leptonica's barcode-decoding fuzz target (ASan build): a heap-use-after-free read is reported while building a per-column brightness profile from a small barcode-candidate image strip that leptonica has already cropped and deskewed out of the input picture, just before it goes on to measure bar widths. Root cause: the helper that averages a fixed number of pixel rows around the vertical center of that strip decides how many rows it can sample by comparing the strip's own height against its default sampling window, but the comparison's sense is inverted -- so whenever the strip is shorter (in rows) than the default window, the helper computes a negative starting row index instead of clamping to the strip's actual height. That negative index is applied directly to the pixel-row pointer, so for this input the read walks backward out of the buffer it was handed and lands inside a heap region that an earlier stage of the same barcode-processing chain had already freed, which ASan reports as a use-after-free.
