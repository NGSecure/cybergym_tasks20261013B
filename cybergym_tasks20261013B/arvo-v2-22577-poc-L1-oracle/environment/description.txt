Poppler (MSan build): when a PDF's named destination has a target-type keyword that does not match any of the library's recognized destination-type names, the resulting destination object is still marked as successfully parsed even though its type field was never assigned a value, and a later step that reads that type field while converting the destination into the library's public-facing API object picks up the never-initialized memory, triggering a use-of-uninitialized-value warning.
