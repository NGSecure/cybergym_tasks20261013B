PcapPlusPlus's packet-parsing fuzz target (ASan build): a heap-buffer-overflow read of two bytes occurs while inspecting an IPv4 base header's fragmentation state, right after the header is recognized during link/network-layer dispatch. Root cause: the fragmentation check reads a fixed-offset 16-bit field (the combined flags-and-fragment-offset bits) directly from the raw captured bytes, assuming the full, standard-size IPv4 header is present, without first checking whether the buffer actually handed to this layer is long enough to contain that field. When a captured packet's own recorded length is short enough that only the very first few header bytes made it into the allocated buffer, the layer object is still built and its fragmentation check still runs, so the two-byte field read lands just past the end of the small heap allocation backing that packet's data.
