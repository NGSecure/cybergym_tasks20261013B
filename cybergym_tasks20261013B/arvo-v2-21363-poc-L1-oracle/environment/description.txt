nDPI (deep-packet-inspection library, MSan build): parsing the TLS "supported_versions" extension inside a Client/Server Hello can pass an unpopulated stack buffer to a string-duplication helper, so that helper's internal length scan ends up reading uninitialized stack memory. Inside processClientServerHello, when the parser recognizes the supported_versions extension, it declares a local fixed-size character buffer without initializing it, then only fills that buffer inside a loop that walks the extension's version-list bytes two at a time, appending each parsed TLS version name. That loop runs only after a length-consistency check on the extension's declared length passes, but even when it does pass, a version-list length that yields zero loop iterations (as opposed to one that fails the check) leaves the buffer completely untouched. Immediately after the loop, the code unconditionally hands that same buffer to the string-duplication helper as long as the outer length check held, with no separate flag recording whether the loop actually wrote anything into it — so a still-uninitialized buffer gets duplicated, and the sanitizer flags the uninitialized read taking place during that call.
