PcapPlusPlus DNS parsing (MSan build): when decoding a resource record's domain name, following one valid name-compression pointer causes a nested call into the same label-decoding logic to resolve the location it points to; that nested call can itself encounter an out-of-bounds compression pointer, and its own early-return-on-error path leaves the temporary buffer it was given without any explicit terminator. Root cause: the outer call then copies characters out of that temporary buffer by scanning byte-by-byte for a terminating zero, but because the buffer was never zero-initialized before the nested call and the nested call's failure path never wrote one either, the copy loop reads uninitialized stack memory past whatever the nested call actually produced.
