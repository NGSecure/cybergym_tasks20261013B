A MemorySanitizer use-of-uninitialized-value warning fires while converting a double-precision floating-point value down to single precision as part of emulating a VFP-style narrowing conversion instruction on the (little-endian) AArch64 configuration of the CPU model. Before any rounding or special-case handling happens, the conversion routine first inspects the source value's sign, exponent, and significand bits to decide whether it is a NaN, a denormal that needs flushing, or an ordinary finite number; those very first field extractions are what trip the sanitizer, because the 64-bit source operand comes from a floating-point/vector register that the fuzz harness's minimal per-input CPU setup never fully populated before the translated instruction stream read it. In other words, the crash is exposed simply by getting attacker-controlled machine code to execute a double-to-single conversion whose source register was never explicitly written earlier in that same short, harness-driven instruction sequence, rather than by any special bit pattern in the value itself.
