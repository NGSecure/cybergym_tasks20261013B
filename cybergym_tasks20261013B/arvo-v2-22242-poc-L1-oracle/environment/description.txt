RDKit's SMILES parser (smiles_string_to_mol_fuzzer, ASan build) suffers a container-overflow READ of a pointer-sized (8-byte) element when it parses a SMILES string that closes a branch with an extra, unmatched ')' that has no corresponding open branch. Root cause: the grammar action that handles a branch-closing token first checks whether its stack of open-branch atom indices is empty; when it is empty (there is nothing left to close), the vulnerable code only reports a parser error and then keeps executing the rest of that same action instead of stopping the parse right there. The rest of that action then pops from the already-empty branch stack and indexes into the vector holding pointers to the molecule object(s) assembled so far, using a value that is no longer a live index into that vector at this point in the malformed derivation, so the read lands inside memory the vector has reserved but not yet constructed, and ASan's container instrumentation flags it as an out-of-bounds read.
