PcapPlusPlus's packet-parsing fuzz target (ASan build): a heap-buffer-overflow read of a single byte occurs while parsing a TLS/SSL handshake message that asks the peer to present a client certificate, specifically while walking a short list of acceptable certificate-type bytes that the message declares up front. Root cause: the code that limits how many of these type bytes it will read clamps the attacker-controlled count by subtracting two small fixed header sizes from the handshake message's own declared length, but never first confirms that the declared length is at least that large; when the declared length is at or barely above that minimum, the subtraction wraps around (unsigned integer underflow) into an enormous value, so the intended clamp silently fails to trigger. The raw, unclamped count byte read straight from the packet is then used as the loop bound, and the loop walks one byte past the end of the small heap allocation backing the captured packet's bytes.
