GraphicsMagick's WPG (WordPerfect Graphics) reader is fuzzed directly at its decode entry point, and a two-byte heap-buffer-overflow write occurs while unpacking a run-length-encoded, palette-indexed raster scanline. The WPG container is a sequence of typed sub-records that are all processed against the same running Image object; when an earlier sub-record embeds and force-reads a nested image blob of a different, unrelated graphics format, the reader replaces its current Image with that freshly decoded nested image, complete with its own tiny pixel cache sized to the nested image's small dimensions. A later sub-record in the same file then reinterprets that same, now-undersized Image object as a much larger raster bitmap, resetting its declared width and height before handing it to the scanline unpacker. Filling each scanline requires acquiring a pixel-cache row sized to the new, larger width, which triggers a cache resize that can be refused by the memory/resource-limit subsystem; when that row-acquisition step reports failure, the byte-by-byte unpacking loop does not stop but simply records the error and keeps consuming input and advancing through later scanlines instead of aborting. On one of those later rows the row-acquisition call unexpectedly succeeds against backing storage that was never actually grown to the new width, so the per-pixel index-writing loop, driven by the large declared column count, walks past the end of the still-undersized allocation and corrupts adjacent heap memory.
