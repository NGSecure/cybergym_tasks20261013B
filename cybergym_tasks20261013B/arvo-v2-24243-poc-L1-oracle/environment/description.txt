OTS (OpenType Sanitizer)'s libFuzzer target (ots-fuzzer, MSan build): sanitizing a two-font TrueType Collection (TTC) whose two subfonts share byte-identical table directories triggers a use-of-uninitialized-value warning inside the cvar (CVAR) variation-data validator. That validator looks up the current subfont's fvar (FVAR) table to learn its declared axis count, then loops that many times over per-axis tuple coordinates. The collection's fvar table is only a handful of bytes long -- too short to hold even its own fixed-size header -- so header decoding bails out partway through and the table object's axis-count field is left as never-written heap memory; the table is nonetheless marked "dropped" (an internal don't-serialize flag) rather than freed or cleared. Because both subfonts point at the exact same physical table bytes, a cross-subfont table cache hands the very same half-populated, already-dropped fvar object to the second subfont's lookup without re-checking whether it is actually usable. The second subfont's own per-font "variations were dropped" bookkeeping was never triggered (it is independent, fresh state per subfont), so its cvar table is validated normally, its fvar lookup succeeds, and the untouched axis-count field is trusted as the bound for the tuple-coordinate loop -- so the never-written value flows straight into that loop and is flagged by MemorySanitizer.
