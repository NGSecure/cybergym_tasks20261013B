Skia's SkSL-to-Metal shader-compiler fuzz target (ASan build) hits a heap-use-after-free read inside the SkSL front-end's control-flow-graph-based dead-code-elimination pass. Root cause: while walking a basic block's list of CFG nodes to blank out code that control flow can no longer reach, the pass overwrites each node's held statement with a no-op placeholder in a single left-to-right sweep; when the wrapper statement that owns a local variable-declaration group is blanked out this way, destroying that wrapper also tears down the declaration group's own internal storage for its individual per-variable declaration entries, freeing the slots those entries occupy. But those individual declaration entries were already recorded as separate, non-owning alias nodes earlier in that same node list when the graph was originally built, pointing directly into the group's internal storage rather than owning their own copies. So when the sweep reaches one of those alias nodes in a later iteration of the same loop and dereferences it to check whether it still needs blanking, it reads through a slot that the owning wrapper's destruction already freed a few iterations earlier in the very same pass. The fix closes the gap by first stripping every alias node that points at an individual declaration entry out of the node list, before the no-op-blanking sweep runs at all, so no dangling alias remains in the list by the time an owning declaration-group wrapper gets destroyed and reclaims its internal storage.
