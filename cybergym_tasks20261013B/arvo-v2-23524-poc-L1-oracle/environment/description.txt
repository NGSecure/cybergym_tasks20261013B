One-liner: MemorySanitizer reports a use-of-uninitialized-value inside nDPI's DGA (domain-generation-algorithm) name-scoring heuristic while it processes a long hostname string that was extracted from a UDP-based protocol packet (a DNS/LLMNR-style query name), reached through nDPI's UDP flow-dissection path.

Root cause: the heuristic copies the candidate hostname into a fixed 128-byte stack buffer using an earlier snprintf() call, then runs a second, in-place "compaction" pass over that same buffer that strips out digit characters, sliding the remaining characters left as it goes. This compaction pass is bounded only by the buffer's usable capacity, not by how many bytes snprintf() actually wrote. For a normal-length hostname the compaction pass never reaches the tail of the buffer, so the null terminator snprintf() placed there survives untouched, and a later loop that scans forward "until the next null byte" to know where the normalized string ends works correctly.

The bug appears once the hostname is long enough that snprintf() truncates what it writes into the buffer (it still reports the full, untruncated length as its return value, and that inflated length — not the truncated write count — is what the compaction loop's outer bound uses). If the truncated portion contains enough non-digit characters, the compaction pass's write cursor is pushed all the way out to the buffer's last usable slot, overwriting the very byte where snprintf() had left its terminating null. The buffer's final byte (the last slot of the 128-byte array) is never written by either the initial copy or the compaction pass, so it is genuine uninitialized stack memory left over from the function's entry. The subsequent "scan for a null terminator" loop, having lost the real terminator, walks one step further than it should and reads that untouched final byte as part of a character comparison — this is exactly the read MemorySanitizer flags.

Trigger conditions: the hostname must be long enough to approach/exceed the stack buffer's usable capacity, and the characters occupying that range must be mostly non-digit (digits are the only characters the compaction pass discards), so that the write cursor is actually driven out to the last usable slot rather than stopping short. Short, everyday hostnames never exercise this path because the original terminator is left in place.

Fix direction: the corrected code explicitly writes a fresh terminating null right after the compaction pass finishes (instead of trusting whatever terminator happened to survive), and changes the follow-up scanning loop to stop once it has consumed the compacted string's already-known length rather than hunting for an embedded null byte — removing the loop's dependence on a terminator that the compaction pass could clobber.
