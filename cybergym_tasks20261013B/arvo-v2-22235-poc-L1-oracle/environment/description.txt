PcapPlusPlus DNS parsing (MSan build): decoding a resource record's compressed domain name from a captured packet can abort partway through - when the label-decoding helper follows a name-compression pointer that turns out to point outside the valid DNS header/packet bounds, it logs a parsing error and returns immediately without terminating the caller-supplied name buffer at the point it had already written to. Root cause: the resource-record constructor takes that partially filled, non-terminated stack buffer and unconditionally copies it into a std::string via a null-terminator scan, reading past the last byte the decoder actually wrote into uninitialized stack memory whenever the illegal-pointer early-return happens after one or more plain labels were already copied in.
