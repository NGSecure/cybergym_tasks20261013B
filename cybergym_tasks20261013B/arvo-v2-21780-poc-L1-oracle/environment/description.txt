nDPI's AFL-based packet-processing fuzz target (ASan build): a 1-byte heap-buffer-overflow READ occurs while nDPI's TCP-flow protocol dissector is fingerprinting traffic on port 1521 (the well-known port for a common relational-database wire protocol). Root cause: the dissector for that protocol reads several fixed byte offsets from the current TCP segment's payload and compares them against a short magic-byte signature to recognize the protocol, but it does not first confirm that the payload actually contains that many bytes. When a TCP segment destined for (or originating from) that port carries a payload shorter than the signature being matched, one of these fixed-offset reads lands exactly one byte past the end of the heap buffer holding the captured packet payload, producing the out-of-bounds read reported by AddressSanitizer. The upstream fix adds an explicit payload-length guard ahead of the signature comparison so the chained byte checks short-circuit (and the out-of-range offset is never dereferenced) whenever the payload is too short for the pattern being tested.
