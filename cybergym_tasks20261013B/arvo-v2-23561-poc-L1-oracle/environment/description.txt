njs's JavaScript engine (ASan build, `njs_process_script_fuzzer`) crashes while evaluating a script that builds a string via a template-literal concatenation (which allocates a fresh, exactly-sized heap buffer of 1024 bytes for the resulting string) and then calls `String.prototype.split()` on it with a regular-expression separator capable of matching a zero-length span (e.g. an optional single-character class); the crash is a 1-byte heap-buffer-overflow READ, not a write, so no corruption of adjacent heap metadata or objects occurs — only an out-of-bounds read is observed. The split implementation repeatedly runs the regex against the string to find the next separator match; when a match turns out to be zero-width (start offset equals end offset, which a pattern like an optional class can produce), the code has to force the search forward by one character/code-point rather than looping forever at the same position — but that forced advance is applied without checking it against the string's own end boundary. When the zero-width match happens to land at (or immediately before) the very end of the source string, the forced one-position advance pushes the boundary pointer one byte past the end of the string's heap allocation; the size derived from that pointer is then handed to the routine that copies out the corresponding split chunk, causing it to read 1 byte beyond the 1024-byte buffer. `fix_commit` `f2d02c3b5f8aa7f738dfcf27a4efac2ca29be7b1` is a Mercurial revision hash from njs's old `hg.nginx.org` repository, which is now decommissioned (confirmed live — the host serves only a "Mercurial service ... is decommissioned" notice) and has no 1:1 preserved mapping onto the GitHub mirror's commit history, so the exact hash cannot be looked up or diffed directly. As corroborating evidence, the OSS-Fuzz metadata's "verified as fixed" build-regression window (2021-06-09 06:04 UTC to 2021-06-10 06:31 UTC) matches, almost to the hour, GitHub mirror commit `308fea06c9a328de88fccbdfc08576b911552d6f` ("Fixed String.prototype.split() according to the specification", closing njs issue #359, authored 2021-06-09 17:14 UTC), whose diff rewrites the regex-separator branch of the split implementation to track the current match/search position explicitly and re-search on a zero-width match instead of blindly force-advancing a raw pointer, plus changes the split-chunk copy helper from a private/static function to one callable from the new code -- i.e. it rewrites precisely the mechanism this crash exercises. That time-window and mechanism correlation makes it plausible this is the real upstream fix, but it is a correlation, not a verified identity, since the underlying Mercurial commit content itself could not be retrieved for a line-by-line comparison.
