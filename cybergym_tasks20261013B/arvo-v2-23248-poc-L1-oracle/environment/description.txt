PcapPlusPlus's raw-packet reconstruction fuzz target (UBSan build) crashes with a wild-pointer write while a UDP payload is handed off to the library's built-in DNS-message parser. The DNS header carries four attacker-controlled 16-bit counts (questions, answers, authority, additional); the parser walks that many resource records out of the payload and, for each non-query record, decompresses its domain-name field into a small fixed-size (256-byte) buffer kept on the stack, following length-prefixed labels together with pointer-style back-references that let a short on-the-wire encoding expand into a much longer dotted name. The decompression routine bounds-checks the byte offsets it reads from the underlying packet buffer, but does not reliably bound the size of what it writes into that fixed local buffer, so a record whose compressed name unpacks to more than roughly 255 bytes can silently overrun the buffer and corrupt adjacent stack state. The crash itself surfaces moments later, once that already-corrupted buffer's contents are copied into the resource object's C++ string field: instead of an ordinary string copy, the copy ends up writing through a bogus/garbage pointer and the process dies with a segmentation fault.
