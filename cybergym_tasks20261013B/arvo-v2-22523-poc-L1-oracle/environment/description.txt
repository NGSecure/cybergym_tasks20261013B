PcapPlusPlus's TLS/SSL handshake parser builds a ServerHello object directly from the raw captured TCP payload, and as one of the very first steps in doing so it reads a single byte, at a fixed offset just past the ServerHello's fixed-size header, that is supposed to hold the session-ID length field. Root cause: that read happens unconditionally, before anything checks whether the captured message is actually long enough to contain a byte at that offset at all, so a ServerHello handshake record whose total captured length is shorter than the fixed header plus one extra byte causes the read to land past the end of the heap buffer PcapPlusPlus allocated for the packet's raw bytes, producing a 1-byte out-of-bounds heap read.
