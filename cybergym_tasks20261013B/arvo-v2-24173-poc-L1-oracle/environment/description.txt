A wild-address read crashes immer's C++ persistent-vector fuzz target (ASan build) while an in-place, copy-on-write update of a single element is applied to a relaxed radix-balanced tree (RRB-tree). The vector under test was assembled by repeatedly concatenating pseudo-random sub-vectors produced earlier in the same fuzzer run. Concatenating two RRB-trees can produce an irregularly-shaped ("relaxed") internal node whose children hold different numbers of elements; such a node carries a small per-child running-size table so that a lookup by global index can jump straight to the right child and compute a local offset without visiting every sibling. The harness driving these concatenations bounded how large the resulting vector was allowed to grow using an approximation based on the numeric range of the size type, rather than the smaller capacity that the tree's actual branching and leaf-width parameters can structurally address once enough concatenations stack additional levels onto the tree. Once the tree's real depth outgrows what that capacity allows, its size bookkeeping no longer matches its real shape. The next single-element update walks down through this over-deep, inconsistent structure; the step that resolves which child branch a given index falls into, and what the local offset within that child is, derives an offset from the stale size table that points outside the node's real child array, and the read used to continue the walk through that offset lands on an unmapped address.
