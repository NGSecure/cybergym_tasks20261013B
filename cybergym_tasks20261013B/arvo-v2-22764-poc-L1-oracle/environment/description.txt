Leptonica's barcode-decoding fuzz target (MSan build): a use-of-uninitialized-value warning fires inside the signal-processing step that turns a barcode strip's per-column brightness profile into a list of threshold-crossing positions, specifically at the point where a sampled brightness value is compared against a scan threshold. Root cause: the same brightness-profile builder implicated in this crash family decides how many pixel rows to average around the vertical center of an extracted barcode-candidate strip using an inverted size comparison, so for a strip shorter than its default sampling window it starts averaging from a negative row offset and ends up producing column values pulled from out-of-bounds pixel reads instead of real image data. For this particular input the out-of-range memory happens to be addressable but was never written by leptonica, so nothing faults at read time -- the tainted, never-initialized value simply propagates as data until it is used in a numeric comparison several processing steps further down the pipeline, which is where the sanitizer first flags it.
