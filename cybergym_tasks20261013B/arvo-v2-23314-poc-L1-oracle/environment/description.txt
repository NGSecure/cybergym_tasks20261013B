RDKit molfile parsing (MSan build): parsing a V2000/V3000 CTAB whose substance-group block includes a coordinate record attached to one of the group's boundary bonds triggers a membership check that linearly scans one of the group's small per-index bookkeeping lists for a caller-supplied bond index. That scan reads a list element MemorySanitizer never sees written by a real value. Following the sanitizer's own value-origin trace: the tainted list element was produced earlier in the same parse by the group's atom-bookmark-resolution helper, which looks up whichever atom is currently registered under a given molfile-internal bookmark number and records that atom's index into one of the group's lists - but the atom object it resolves to had, moments earlier in the same file, been freed and swapped out for a replacement while handling an unrelated ring-bond-count / query-atom substitution directive, and nothing along that substitution path clears or updates the bookmark record that still points at the discarded atom. The resolver therefore hands back a pointer into already-freed memory, the numeric value copied out of it and appended to the group's list is garbage rather than a genuine index, and the corruption only becomes externally visible once a later record in the same substance group performs a real lookup against that list.
